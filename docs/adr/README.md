# Architecture Decision Records

Every meaningful design decision reached in the design interview is recorded here as an
ADR so the "why" survives alongside the code.

## Status vocabulary

- **Proposed** — decided during the interview, not yet accepted into the codebase.
- **Accepted** — the codebase implements this decision.
- **Superseded** — replaced; points to the ADR that supersedes it.

## How a decision becomes an ADR

1. The interview surfaces a fork (two or more defensible designs with real consequences).
2. We narrow it down to an explicit decision.
3. We write the ADR capturing context, the decision, and the tradeoffs.
4. New terms get added to `../glossary.md` in the same step.
